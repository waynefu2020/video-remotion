# 制作后台

这份文件只给执行任务的 Agent 看，不向运营用户展示。

## 现有工具

工作目录是 `ideashell-video/`。

- `render.py`：文字、圆角卡片、图标、阴影、贴图、缓动和小红书安全区。
- `audio.py`：音乐乐器、鼓组、转场声和 UI 音效。
- `timeline.py`：品牌色和基础时间轴。
- `new_video.py`、`templates/`：新视频的可运行起点。
- `assets/`：logo 和设备画面。

现有三条片子提供不同能力，不要整条复制：

| 想复用的能力 | 先读 |
| --- | --- |
| 方格逐字输入、标红、吹走、重排、飞进待办、日历 | `schedule_timeline.py`、`schedule_render.py`、`schedule_audio.py` |
| 时间隧道、记忆节点、文件吞入、翻页、表格对比 | `memory_timeline.py`、`memory_render.py`、`memory_audio.py` |
| 录音转文字、笔记墙、来源卡片、设备 UI | `timeline.py`、`render.py`、`audio.py` |

## 新片结构

每条新片至少有四个文件：

```text
<slug>_timeline.py   所有文案、段落和动作时间
<slug>_render.py     画面
<slug>_audio.py      音乐和音效
build_<slug>.sh      一键生成成片
```

可以用：

```bash
cd ideashell-video
python3 new_video.py <slug> "<主题>"
```

生成后要按确认过的分镜重写，不能直接交付模板片。

## 画面原则

1. `render(t)` 必须是可跳转的：任意给一个时间都能画出正确的一帧。
2. 所有时间写在 timeline 文件，画面和音效共同读取，避免手工对齐两套时间。
3. 一段一个 `scene_*` 函数。转场前后允许短暂重叠，不要硬切空白。
4. 动效要有因果：
   - 文字被吹走后，原位置收紧。
   - 文字飞进卡片后，卡片里才出现对应内容。
   - 方格变成日历时，沿用原有格线和位置。
5. 信息层级最多三层：主标题、核心内容、辅助说明。
6. 一屏不要同时让超过两个区域运动。
7. `rrect`、`txt`、`asset` 等缓存图要继续绘制时先 `.copy()`。
8. 叠放顺序：背景 → 容器 → 静态内容 → 飞行元素 → 高光与前景。
9. 透明飞行元素容易透出底图；必要时保持不透明。
10. 英文、数字和时间不要逐字拆开，作为一个视觉单元。

## 小红书安全区

最终画面必须经过：

```python
return xhs_safe(img, PAPER)
```

现有 `xhs_safe` 会把满幅画面缩到 86%，居中后下移 205px。布局按 1080×1920 写，关键内容仍应遵守：

- 顶部约 260px 不放关键文字。
- 左右裁切后仍保留明显边距。
- 1810px 以下不放关键内容。
- 背景必须填满整张图，不能因缩放留下黑边。

## 音乐和音效

- 48kHz 双声道。
- 默认无人声。
- 动作与声音同帧：打字、标记、吹走、飞入、落位、勾选、落版各有声音。
- 音乐按段落编排，不从头到尾同一强度。
- 关键转场前可留 0.1–0.3 秒呼吸或静音。
- 最终响度目标约 -14 LUFS，结尾自然淡出。

常用音效已经在 `audio.make_sfx` 和 `schedule_audio.py`：

`tick`、`pop`、`pop_hi`、`check`、`whoosh`、`swipe`、`rise`、`mark`、`sparkle`、`impact`、`key`、`blow`、`landN`、`slam`。

## 生成顺序

1. 完成时间轴。
2. 生成关键静帧并逐张打开检查。
3. 完成音频和音效事件。
4. 运行构建脚本生成 MP4。
5. 从 MP4 抽关键帧和联系表。
6. 运行 `references/qa.md` 的检查。
7. 修完问题再交第一版。
